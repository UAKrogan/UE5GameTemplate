MODULE ARCHITECTURE
===================

Dependency graph is strictly one-way; violations are rejected in review:

  Game -> GameActors, GameCore, GameUI, GameUtils
  GameActors -> GameUtils (+ GAS modules, EnhancedInput, InputCore, AIModule,
                ModularGameplay, GameFeatures)
  GameCore   -> GameUtils (+ GAS modules, DeveloperSettings;
                private: UMG, Slate, SlateCore, Json)
  GameUI     -> GameUtils (+ UMG, CommonUI, CommonInput, InputCore,
                DeveloperSettings, GameFeatures; private: Slate, SlateCore)
  GameUtils  -> no local deps

GameActors/GameCore/GameUI must never depend on each other. When a design
conflicts with the graph, the graph wins - bridge with soft object paths,
delegates, or data assets. Existing bridge decisions:
- UI configuration lives in UAtlasUIDeveloperSettings (GameUI), not in
  GameCore's settings; GameCore stores only soft paths for UI assets.
- GameCore's loading screen subsystem handles its widget generically as
  UUserWidget via a soft class path.
- AAtlasPostLoadTrigger lives in GameCore (not GameActors) because it exists
  solely to call the transition subsystem.

Module responsibilities
- Game: thin host. UAtlasGameInstance bootstrap only. IMPLEMENT_PRIMARY_GAME_MODULE.
- GameUtils: log categories (LogAtlas, LogAtlasActors, LogAtlasCore, LogAtlasUI,
  LogAtlasUtils), ATLAS_LOG_* / ATLAS_CHECK / ATLAS_ENSURE / ATLAS_ENSURE_MSG /
  ATLAS_LOG_DEBUG macros, FAtlasScopedLog. Nothing else.
- GameCore: runtime orchestration + services (details below).
- GameActors: GAS-ready actor foundation + movement/vehicles/mounts (below).
- GameUI: Common UI layer stack + widgets + glyphs (below).

Macro rule: export macro matches module (GAMECORE_API etc.). All logging goes
through GameUtils macros; never raw UE_LOG in production code.
Note: ATLAS_ENSURE_MSG expands to an if-statement - it cannot be used inside
an expression/condition (ATLAS_ENSURE can).


RUNTIME BOOTSTRAP
=================

1. Engine loads modules; config sets /Script/Game.AtlasGameInstance.
2. UAtlasGameInstance::Init() verifies UAtlasGameInstanceSubsystem exists.
3. UAtlasGameInstance::OnStart() calls UAtlasGameFlowSubsystem::StartGameFlow():
   - travels to UAtlasDeveloperSettings::MainMenuMap when set;
   - auto-travel is SKIPPED in PIE (never hijacks the edited map);
   - with no menu map it enters the MainMenu state in place.

Core orchestrator (GameCore)
- UAtlasGameInstanceSubsystem: owns pure C++ IAtlasSystem instances in
  TMap<FName, TSharedPtr<IAtlasSystem>>; RegisterSystems() delegates to
  FAtlasSystemsRegistry::Register() (currently FAtlasSaveSystem +
  FAtlasLoadSystem); InitializeSystems() in registration order,
  ShutdownSystems() in reverse. GetSystem<T>() resolves by
  SupportsInterface(T::InterfaceName()).
- Adding a system: interface in GameCore/Public/Systems/<Name>/IAtlas<Name>System.h
  (extends IAtlasSystem, static InterfaceName()), implementation FAtlas<Name>System,
  register in FAtlasSystemsRegistry::Register().

Engine subsystems in GameCore (UGameInstanceSubsystem)
- UAtlasGameFlowSubsystem: state machine Startup/MainMenu/Gameplay/Paused/
  Transitioning; RequestGameplay/RequestReturnToMainMenu/RequestPause/Resume;
  OnGameFlowStateChanged(Old, New). Pause is state-only (world pause is up to
  listeners).
- UAtlasLevelTransitionSubsystem: single authority for level travel. Lifecycle
  Idle -> PreTravel -> Traveling -> PostLoad -> Idle with re-entrancy guard.
  FAtlasLevelTransitionRequest: DestinationMap (soft), TransitionType,
  TravelOptions, bShowLoadingScreen, bSaveCheckpointBeforeTravel,
  LoadSlotOnPostLoad. Delegates OnPreTravel/OnPostLoad/OnTransitionFailed.
  NotifyLevelLoaded() fired by PostLoadMapWithWorld automatically and by
  AAtlasPostLoadTrigger placed in maps (idempotent). PerformTravel() is
  virtual (OpenLevelBySoftObjectPtr by default) for future seamless travel.
- UAtlasLoadingScreenSubsystem: viewport-level loading screen (Z-order 10000)
  that survives travel by re-adding on PostLoadMapWithWorld; widget class from
  UAtlasDeveloperSettings::LoadingScreenWidgetClass (soft class path, generic
  UUserWidget); OnLoadingScreenShown/Hidden delegates fire even with no widget
  configured.

Settings / asset manager / tags (GameCore)
- UAtlasDeveloperSettings (Project Settings -> Game -> Atlas Framework;
  [/Script/GameCore.AtlasDeveloperSettings] in DefaultGame.ini): StartupMap,
  MainMenuMap, DefaultGameplayMap (soft world ptrs), DefaultPawnData /
  LoadingScreenWidgetClass / ScreenRegistry as soft paths (cross-module),
  loading fade durations, DefaultSaveSlotName, bEnableAutosave,
  AutosaveIntervalSeconds, bSaveCheckpointOnTravel, bAutoActivateGameFeatures.
- UAtlasAssetManager (AssetManagerClassName in DefaultEngine.ini): owns primary
  asset type constants AtlasPawnData, AtlasAbilitySet, AtlasScreenDefinition,
  AtlasInputConfig; logs init.
- AtlasGameplayTags (GameCore/Public/Tags): native tags via
  UE_DECLARE/DEFINE_GAMEPLAY_TAG. Namespaces: Atlas.GameFlow.*, Atlas.UI.Layer.*,
  Atlas.Input.Native.*, Atlas.Input.Ability.*, Atlas.Save.Event.*.
  Convention: Atlas.Category.Subcategory; feature plugins declare their own.


GAS / ACTOR FOUNDATION (GameActors)
===================================

Actor hierarchy
- AAtlasPawn (APawn) -> AAtlasVehiclePawn, AAtlasMountPawn
- AAtlasCharacter (ACharacter - kept for CharacterMovement/animation)
- AAtlasPlayerController, AAtlasAIController
- AAtlasGameMode (AGameMode - match state), AAtlasGameState (AGameState)
- AAtlasPlayerState (owns the player ASC)
All expose empty Initialize*() virtuals as game-project hooks; all are Modular
Gameplay receivers (AddGameFrameworkComponentReceiver in PreInitializeComponents,
NAME_GameActorReady sent in BeginPlay, RemoveReceiver in EndPlay).

ASC ownership
- Player pawns: UAtlasAbilitySystemComponent lives on AAtlasPlayerState
  (survives respawn; net update frequency raised to 100). Avatar assigned on
  possession by the pawn extension.
- AI pawns: pawn-owned ASC created by UAtlasAbilityExtensionComponent from
  AAtlasAIController::OnPossess; torn down on unpossess.
- Replication mode Mixed set in the ASC constructor.

UAtlasAbilitySystemComponent additions
- AbilityInputTagPressed/Released(FGameplayTag): tag-based activation via
  spec dynamic source tags (ABILITYLIST_SCOPE_LOCK iteration).
- GrantAbilitySet/RevokeAbilitySet(FAtlasAbilitySetHandle&): authority only;
  grant order attribute sets -> effects -> abilities; OnAbilitiesGranted.

Data assets
- UAtlasAbilitySet: GrantedAbilities (class + level + InputTag),
  GrantedAttributeSets, GrantedEffects. FAtlasAbilitySetHandle is C++-only.
- UAtlasPawnData: PawnClass, AbilitySets, InputConfigs, CameraConfig.
- UAtlasInputConfigData: MappingContext + Priority + AbilityBindings
  (InputAction soft ptr -> Atlas.Input.* tag).
- UAtlasCameraConfig: spring arm settings, FOV, blend hints.
- UAtlasBaseAttributeSet: ATLAS_ATTRIBUTE_ACCESSORS macro, clamp pattern,
  example replicated Level attribute. UAtlasBaseGameplayAbility:
  InstancedPerActor, InputTag, avatar/controller/ASC helpers.

Initialization flow (player)
- Game mode resolves pawn class from DefaultPawnData when set.
- PossessedBy/UnPossessed/OnRep_Controller/OnRep_PlayerState all route to
  UAtlasPawnExtensionComponent::HandleControllerChanged(); OnRep_PlayerState is
  the client-side init trigger (PlayerState may replicate after the controller).
- InitializeAbilitySystem is idempotent; grants pawn data sets on authority;
  fires OnAbilitySystemInitialized/Uninitialized (FSimpleMulticastDelegate).
- SetupPlayerInputComponent (owning client) forwards to the controller's
  UAtlasInputExtensionComponent::InitializeForPawn: applies mapping contexts,
  binds ability actions on the pawn's EnhancedInputComponent
  (Started -> pressed, Completed -> released). Bindings die with the pawn's
  input component; contexts are removed in OnUnPossess.

Movement / vehicles / mounts / camera (phase 11)
- UAtlasMovementExtensionComponent: replicated EAtlasMovementMode
  (None/Walking/Falling/Swimming/Flying/Custom/InVehicle/Mounted) with
  rep-notify rebroadcast; auto-syncs with UCharacterMovementComponent via
  MovementModeChangedDelegate; EnterVehicle/ExitVehicle and MountRider/Dismount
  (authority only) save/restore the previous mode, disable/enable the pawn's
  own movement component, attach/detach at sockets. RequestMovementModeChange
  rejects the attachment modes.
- AAtlasVehiclePawn: no physics shipped; GetVehicleMovementComponent() resolves
  whatever the game adds; Seat_<N> socket convention; GetSeatAttachComponent
  overridable. UAtlasVehicleExtensionComponent: TryEnterVehicle (seat -1 =
  first free), ExitVehicle, seat bookkeeping with weak refs, optional
  PassengerInputConfig/PassengerCameraConfig, C++/BP hooks + delegates.
- AAtlasMountPawn + UAtlasMountExtensionComponent: single rider, RiderSocket,
  CanBeRidden(), RiderInputConfig/RiderCameraConfig.
- Input routing: the input extension listens to OnMovementModeChanged and
  suppresses the pawn data default mapping contexts while InVehicle/Mounted
  (contexts only - ability bindings stay bound, so resume never double-binds).
- UAtlasCameraExtensionComponent (optional): applies UAtlasCameraConfig to the
  owner's spring arm/camera; default from pawn data, vehicles/mounts
  PushCameraConfig/ClearPushedCameraConfig around attachment.

Feature actions in GameActors
- UAtlasGameFeatureAction_AddAbilities: extension-handler based; covers live
  and late-spawning pawns; defers grants until OnAbilitySystemInitialized when
  the pawn is not possessed yet; revokes on deactivate.
- UAtlasGameFeatureAction_AddInputConfig: applies configs to live and
  late-spawning local AAtlasPlayerControllers.


UI ARCHITECTURE (GameUI)
========================

UAtlasUISubsystem (UGameInstanceSubsystem)
- Owns UAtlasRootWidget (lazy-created, re-added to viewport after travel).
- PushScreen(FName, Context)/PopScreen/PopAllScreens/IsScreenActive/
  GetActiveScreen; screens resolved by ID via UAtlasScreenRegistry
  (UAtlasUIDeveloperSettings::ScreenRegistry). Definitions:
  UAtlasScreenDefinition (WidgetClass soft, TargetLayer, RequestedInputMode,
  bSingleInstance; primary asset type AtlasScreenDefinition).
- RegisterScreen/UnregisterScreen: runtime registrations (used by feature
  actions) take precedence over authored entries; unregister pops if active.
- ShowHUD/HideHUD push/pop HUDScreenId (default "HUD"); GetActiveHUDWidget.
- ShowModal(id, FAtlasModalPayload, FAtlasModalResultDelegate)/DismissModal:
  modal must be a UAtlasModalWidget; result fires exactly once.
- ShowNotification(FAtlasNotificationPayload): toast on Notification overlay,
  auto-removed after duration.
- ShowLoadingScreen/HideLoadingScreen: root-widget Loading layer (for travel
  use the GameCore subsystem instead).
- Input mode derived from the top-most active screen (highest layer, then
  most recent); EAtlasInputMode Game/Menu/GameAndMenu/GamepadCursor applied to
  the first local player controller; OnInputModeChanged.
- Delegates: OnScreenPushed/OnScreenPopped(FName).

UAtlasRootWidget layers (bottom to top)
- GameLayer/MenuLayer/ModalLayer: UCommonActivatableWidgetStack.
- NotificationLayer/LoadingLayer: UOverlay.
- BindWidgetOptional: a Blueprint root may bind them; otherwise constructed
  procedurally so the UI works with zero content assets.

Widget bases
- UAtlasActivatableWidget (UCommonActivatableWidget): InitializeWithContext,
  RequestedInputMode, bDismissOnBack. UAtlasMenuWidget, UAtlasModalWidget
  (Confirm/Cancel + payload), UAtlasHUDWidget (named element slots,
  AddHUDElement/RemoveHUDElement for feature injection),
  UAtlasNotificationWidget and UAtlasLoadingScreenWidget (plain UUserWidget -
  must not require activation).

Glyphs
- UAtlasGlyphSubsystem (ULocalPlayerSubsystem) wraps Common Input device
  detection -> EAtlasInputDevice (KeyboardMouse/Xbox/PlayStation/Generic);
  OnInputDeviceChanged; GetGlyphForKey via UAtlasInputGlyphData
  (key -> texture per device) from UAtlasUIDeveloperSettings.

UAtlasUIDeveloperSettings (Project Settings -> Game -> Atlas UI)
- RootWidgetClass, RootWidgetZOrder, ScreenRegistry, HUDScreenId,
  LoadingScreenWidgetClass, NotificationWidgetClass, InputGlyphData,
  bAutoDetectInputDevice, navigation options.

Feature actions in GameUI
- UAtlasGameFeatureAction_AddScreens: register/unregister runtime screens.
- UAtlasGameFeatureAction_AddHUDElements: inject widgets into HUD slots,
  re-adding when a HUD screen is pushed later.


SAVE / LOAD ARCHITECTURE (GameCore)
===================================

Layering
- IAtlasSaveSystem / IAtlasLoadSystem (interfaces)
- FAtlasSaveSystem / FAtlasLoadSystem (TSharedFromThis implementations)
- FAtlasSaveScheduler (priority queue Manual > Event > Autosave; event
  debounce 2 s; timer autosave 300 s via FTSTicker)
- FAtlasAutosaveManager (ring buffer Autosave_0..4; reserved index persisted
  in AutosaveIndex.sav; critical-section guarded)
- FAtlasBinaryWriter / FAtlasBinaryReader (versioned chunked binary; chunk
  names Header/WorldSnapshot/ActorSnapshot/DataChunk shared as inline
  constants in AtlasBinaryWriter.h)
- FAtlasSaveCollector (game-thread world walk; captures IAtlasSavable actors
  and components into FAtlasWorldSnapshot)
- FAtlasSaveMigrationManager (registry of sequential vN->vN+1 world snapshot
  migrations; invoked by the reader when the payload version is older;
  missing step fails the load)
- FAtlasSaveSlotManifest (JSON manifest Saved/SaveGames/SaveManifest.json,
  updated after every successful save; AddSlot/RemoveSlot/GetAllSlots)
- FAtlasFileStorage (temp-file + rename writes, 256 MiB cap, slot name
  sanitization)

Actor participation
- UAtlasSavableComponent: stable FGuid ActorId (regenerated on duplication);
  required for collection; load resolves actors by GUID and respawns missing
  ones from the recorded class path.
- IAtlasSavable: CaptureState/RestoreState with chunked
  FAtlasSaveContext/FAtlasLoadContext (game thread).
- Adapters: UAtlasGASSaveAdapter (attributes + active effects; approximate
  effect duration restore, heuristic cooldown detection),
  UAtlasInventorySaveAdapter (stub inventory items).

Threading
- Requests and collection on the game thread; serialization + file I/O async
  (thread pool) with completion marshalled back via AsyncTask(GameThread).
- bSaveInProgress / bLoadInProgress are std::atomic<bool>.

Level transition integration
- bSaveCheckpointBeforeTravel: event-priority save to "Checkpoint_Travel" in
  the pre-travel phase (world state collected synchronously before travel).
- LoadSlotOnPostLoad: RequestLoad of that slot right after post-load.

Still-valid caveats (inherited from the original implementation)
- FAtlasSaveGameSnapshot / UAtlasSaveGame key-value APIs exist but are NOT
  integrated into the binary world snapshot path; LoadedSnapshot key/value
  getters return nothing after a binary load. Unify or remove when asked.
- Component chunks are keyed by component index + name; reordering/renaming
  components between save and load breaks restore matching.
- Load does not destroy world actors absent from the snapshot.
- No save/load completion delegates exposed; no Blueprint-facing save/load
  API (systems are C++ shared pointers behind the subsystem).
- GAS adapter effect restore is approximate (fresh durations).

SHORT HANDOFF SUMMARY
=====================

UE 5.7 modular C++ template ("Atlas" framework) with five one-way-dependency
modules: Game (thin host), GameCore (orchestrator subsystem + game flow,
level transitions, travel-surviving loading screen, developer settings, asset
manager, native tags, hardened async save/load with migrations and a JSON
slot manifest), GameActors (GAS-ready actors with PlayerState-owned player
ASC, extension components for pawn/ability/input/movement/vehicle/mount/
camera, tag-based Enhanced Input -> ability activation, data-asset-driven
pawn configuration, Modular Gameplay receivers + custom feature actions),
GameUI (Common UI layered screen stack driven by a screen registry, modal/
notification/loading services, input mode management, glyph subsystem), and
GameUtils (logging/assertion macros used everywhere).

All planning phases (0-11) are implemented and committed one per phase; both
build targets compile clean. What remains is editor-authored content, runtime
validation in PIE, automated tests, and the small remnants listed in
docs/plan/README.md. docs/guides/ is the authoritative documentation; keep
the module dependency graph inviolate and keep gameplay out of the source
modules.
